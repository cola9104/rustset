# RustSet 功能范围与验收标准

本文定义当前产品边界和完成口径。历史前端与权限迁移过程记录在 `docs/kairos-migration-plan.md` 和 `docs/migration/`，不再作为当前产品定义。

## 当前产品范围

- **系统管理**：认证、用户、部门、岗位、角色、菜单、租户、租户网段、字典、通知、OAuth2、日志、文件与任务。
- **资产中心**：资产台账、网络策略、扫描任务和风险记录。
- **配置管理**：CMDB 模型、属性、实例和关系。
- **基础设施中心**：服务商、机房、区域和安全产品。
- **云管理中心**：云平台、云区域和云厂商接入凭据。
- **业务中心**：业务应用与业务资源。
- **运维中心**：资源工单、审批规则、OpenTofu 开通和 CMDB 回写。
- **AI 大模型**：统一 AI 模型配置、对话、知识库、绘图、音乐、写作与智能运维工具。

CMDB 模型与 AI 模型是两个独立概念：前者定义资产数据结构，后者配置模型供应商和推理连接。所有 AI 业务必须复用 `ai.model_configs`，不得另建重复的大模型配置表或密钥入口。

## 明确不在范围内

- BPM 流程引擎及其前端页面。
- 已删除的 Dioxus 前端。
- 未接入真实执行器的完整漏洞扫描、渗透测试或终端 Agent 平台。
- 仅存在于历史迁移来源、演示数据或上游示例中的功能。

## 完成标准

一个功能只有同时满足以下条件才能标记为完成：

1. 存在真实 Rust 接口和持久化逻辑，不以固定成功响应代替实现。
2. 数据库变更通过新增 SQLx 迁移交付，支持空库初始化和已有库升级。
3. 后端接口具有认证、权限码和租户边界，前端按钮权限与其一致。
4. 前端入口、字段、状态流转和错误反馈可以完成实际业务操作。
5. 关键流程有自动化测试或可重复的联调验收记录。
6. README、技术方案、部署文档和实际入口保持一致。

## 当前需持续验收的外部能力

- 各云厂商凭据的真实连接测试和 Provider 覆盖度。
- OpenTofu 在目标云环境中的 plan、apply、失败恢复和审计。
- 扫描任务在不同网络环境中的可达性、超时与结果准确性。
- 外部 AI 供应商的协议差异、配额、流式输出和异步任务轮询。
